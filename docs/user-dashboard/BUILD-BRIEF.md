## 3. Product language rules

- Statuses use the mapping in specification §7 item 7: PENDING → "Pending review", APPROVED → "Approved", REJECTED → "Declined", CANCELLED → "Cancelled". Settlement is a separate field; "Completed" only with settlement evidence, otherwise "Settlement not confirmed".
- Never use: institutional, audited, verified (unless the record carries verification evidence), guaranteed, instant, secure custody, automated (for a manual operation), "Tier-2 Verified", "2FA Protected", "live" badges, yield, dividend, ROI defaults, "quantitative strategies".
- Copy is sentence case, plain, short. Headings name the customer's decision ("Withdraw", "Deposit BTC"), not marketing claims.
- Money: exact decimal strings, units after the number (`0.10000000 BTC`), fiat estimates labelled "Estimated" with the quote timestamp. Unknown values render an em dash "—" with a specific reason in help text. Zero is `0.00000000 BTC`, never "—"; unknown is "—", never zero.
- Signed changes carry an explicit sign and a text label ("Recorded P/L +120.00 USD, 30 days, ledger method"). Colour never carries meaning alone; do not introduce green/red conventions.
- Deposits and withdrawals are cash flows, not income or profit.

## 4. Tailwind 3 rules for every new file

Use only syntax Tailwind 3.4 compiles. Verify anything unusual by grepping `http://localhost:3000/_next/static/css/app/layout.css` for the escaped class.

| Do not write | Write instead |
| --- | --- |
| `px-(--x)`, `w-(--radix-popper-anchor-width)` | `px-[var(--x)]`, `w-[var(--radix-popper-anchor-width)]` |
| `[--card-spacing:--spacing(4)]` | `[--card-spacing:1rem]` |
| `data-open:x`, `data-closed:x`, `data-active:x` | `data-[state=open]:x`, `data-[state=closed]:x`, `data-[state=active]:x` |
| `data-horizontal:x`, `data-vertical:x` | `data-[orientation=horizontal]:x`, `data-[orientation=vertical]:x` |
| `data-placeholder:x`, `data-checked:x`, `data-disabled:x` | `data-[placeholder]:x`, `data-[state=checked]:x`, `data-[disabled]:x` |
| `has-data-[icon=inline-end]:x` | `has-[[data-icon=inline-end]]:x` |
| `**:data-[slot=kbd]:x`, `*:data-[slot=x]:y` | `[&_[data-slot=kbd]]:x`, `[&>[data-slot=x]]:y` |
| `supports-backdrop-filter:x` | `supports-[backdrop-filter]:x` |
| `not-aria-[haspopup]:x` | drop it (no positional press animation in the dashboard) |
| `text-xs/relaxed` | `text-xs leading-relaxed` |
| `h-screen` | `h-dvh` / `min-h-dvh` |
| `size-(--x)` | `size-[var(--x)]` |

After the Stage B port, opacity modifiers on semantic colours (`bg-primary/80`, `ring-foreground/10`) work through `color-mix` and may be used. Until you have confirmed the port landed (grep the served CSS for `\.bg-primary\/80`), prefer plain tokens.

Utilities that exist in 3.4 and are fine: `size-4`, `data-[state=open]:`, `has-[…]:`, `group-data-[state=open]/name:`, `aria-[expanded=true]:`, `focus-visible:ring-2`, `ring-[3px]`, `text-balance`, `text-pretty`, `tabular-nums`, `truncate`, `line-clamp-2`, `@container` (only if the container-queries plugin were installed; it is not, so do not use `@container`/`@md:`), `min-h-dvh`, `[&_svg]:size-4`, arbitrary properties `[--x:1rem]`.

Class geometry is on the 4pt grid: `p-4 (16)`, `p-6 (24)`, `gap-2 (8)`, `gap-4 (16)`, `gap-6 (24)`, `gap-8 (32)`. Use `h-8` (32px) `size=lg` Buttons for ordinary desk actions, `h-7` for dense table actions. Touch and consequential forms use the `.ca-touch` wrapper from `dashboard.css` (44px controls).

Colours: only semantic tokens (`bg-background`, `bg-card`, `text-muted-foreground`, `border-border`, `bg-primary text-primary-foreground`, `text-destructive`, `bg-secondary`, `bg-muted`, `ring-ring`, `stroke-[var(--chart-1)]`). Never palette utilities (`text-amber-500`, `bg-slate-900`, `text-emerald-500`). Never gradients, blur blobs, glass, glows, `shadow-*` on ordinary cards, `rounded-full` panels, `rounded-xl`/`rounded-2xl`. Card radius is `rounded-lg` (0.55rem) from the shared scale; controls `rounded-md` (0.45rem).

Icons: `@phosphor-icons/react` only, regular weight, `size={16}` inside controls, `size={20}` in navigation, `weight="fill"` only for the selected navigation item. Decorative icons get `aria-hidden="true"`. Icon-only buttons get `aria-label`. Never import `lucide-react` in dashboard files.

Fonts: headings `font-heading` (Space Grotesk), everything else inherits `font-mono` (Geist Mono) from `<html>`. Use the `.ca-*` type-role classes from `dashboard.css` (section 6) instead of ad-hoc `text-[…]` sizes.

## 5. Stage B: compatibility port of owned primitives

Goal: every class in `components/ui/*` emits CSS under Tailwind 3.4 with the geometry documented in `COMPONENTS.md`, with no visual change to the public site (which uses its own `pp-*` CSS on top of Button/Input/Checkbox).

1. `tailwind.config.ts`: make every semantic colour accept opacity modifiers under Tailwind 3 by defining each token as a function:
   ```ts
   const token = (name: string) => ({ opacityValue }: { opacityValue?: string }) =>
     opacityValue === undefined || opacityValue === "1"
       ? `var(--${name})`
       : `color-mix(in oklab, var(--${name}) calc(${opacityValue} * 100%), transparent)`;
   ```
   Apply to background, foreground, card(+foreground), popover(+foreground), primary(+foreground), secondary(+foreground), muted(+foreground), accent(+foreground), destructive(+foreground), border, input, ring, chart 1–5, sidebar tokens. Confirm in the served CSS that `.bg-primary\/80`, `.ring-foreground\/10`, `.bg-destructive\/10`, `.border-border\/60` now exist and that `.bg-primary` is still `background-color: var(--primary)` (Tailwind passes `opacityValue: "var(--tw-bg-opacity)"` for plain usage; handle that case by emitting `color-mix(in oklab, var(--name) calc(var(--tw-bg-opacity) * 100%), transparent)` and setting the opacity variable to 1, or by returning the plain `var()` when the value is not a bare number and equals the utility's own opacity variable; verify the rendered colour is unchanged either way).

Tabs, Sidebar (708 lines), Dropdown Menu, Select, Sheet, Tooltip, Field, Button, Badge, Toggle, Toggle Group, Drawer, Breadcrumb, Avatar, Checkbox, Chart, Sonner, Input, Label, Table, Separator, Skeleton, Collapsible all need review.

## 6. Stage C: shell, theme, primitives, preview frame

### Theme

- `components/dashboard/theme-provider.tsx`: wraps next-themes `ThemeProvider` with `attribute="class"`, `defaultTheme="system"`, `enableSystem`, `storageKey="ca-dashboard-theme"`, `disableTransitionOnChange`, `enableColorScheme`. Mounted by `app/(dashboard)/layout.tsx` and by the dashboard preview layout only. It sets `light` or `dark` on `<html>`; the explicit `:root.light` token block from Stage B makes Light win on a dark OS. Radix portals render to `<body>` and therefore inherit the resolved tokens.
- The user menu offers Light / Dark / System as a radio group. `resolvedTheme` selects logo assets and the QR quiet zone stays black-on-white in both themes.
- Never render user-specific text before hydration in a way that can flash the wrong user: the shell renders a neutral skeleton for the account name until the server-provided `SessionAccount` is available (it is available at SSR time in live mode, so no flash occurs; in preview it is fixture data).
